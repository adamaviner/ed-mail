# @earthdance/mail

Email for Earthdance's Convex apps: sending through Gmail with retries, a log of every email with
its body, failure reporting, saved wording, and the React letter editor and admin page. One npm
package holding a Convex component, the client code apps call from their `convex/` folder, and the
React pieces.

The design and the build stages are in ed-schedule's `docs/email-lib-plan.md`. ed-schedule adopts
the library first; ed-market (the auction app) later.

**Status:** scaffold (stage 0). The component only holds settings so far.

## What was checked before building (2026-11-14)

Checked against https://docs.convex.dev/components (Using, Understanding, Authoring), the official
component template (`get-convex/templates`, `template-component`), and `convex` 1.46 (ed-schedule's
version) and 1.50 (this repo's). Items marked _tested_ were run, not only read.

1. **Environment variables.** By default a component can't read the app's env (only
   `CONVEX_CLOUD_URL` and `CONVEX_SITE_URL`). Since about 1.46 a component can declare typed env in
   `defineComponent(name, { env })`, filled in by the app's `app.use(component, { env })`.
   **The design doesn't use it:** sending runs in the app's own worker action, which reads the Google
   client id/secret and the encryption key from the app's env and hands them to the library's code.
   The component never holds a secret, and an app can't forget to pass one through.
2. **HTTP routes and crons.** A component can define `http.ts`, exposed when the app mounts it with
   `httpPrefix`, but those handlers get no `ctx.auth` and no app env. Nothing documents components
   defining crons. **The design keeps both in the app:** `mail.registerRoutes(http, { path })` adds
   the Google callback to the app's router (ed-schedule keeps `/google/oauth/callback`, already
   registered with Google), and the app's crons call `mail.cleanup` and the digest.
3. **Ids and transactions.** Ids of component tables are plain strings outside the component, and
   `v.id()` can't name another component's table, so the library refers to app rows as
   `ref: { type, id }` strings. A component mutation called from an app mutation commits in the
   same transaction; it is a sub-transaction, so if it throws only its writes roll back and the
   caller may catch and continue. _Tested_ in `src/client/index.test.ts`: when the app mutation
   throws after writing to both, neither write lands.
4. **convex-test.** `t.registerComponent(name, schema, import.meta.glob(...))`. The package exports
   the helper as TypeScript source at `@earthdance/mail/test` (the glob only works when the app's
   Vitest compiles it), the same as `@convex-dev/rate-limiter/test`. _Tested_ from an app installed
   with convex-test 0.0.60 (ed-schedule's) and `convexTest(schema, modules)`; this repo's own tests
   use convex-test's newer `defineTestApp`.
5. **Package layout.** Taken from the official template: `src/component` (with its `_generated`,
   committed, regenerated by `npm run build:codegen`), `src/client`, `src/react`, `src/test.ts`, built
   by `tsc` to `dist`; `package.json` exports `./convex.config.js` and `./_generated/component.js`,
   which is what the Convex CLI needs to bundle the component from `node_modules`. Added `./core` for
   the pure helpers. _Tested_: a scratch app on convex 1.46 installed the package, `convex dev`
   reported "Installed component mail", and a query and mutation through `Mail` worked. Installing:
   - from a release tag, `npm install github:adamaviner/ed-mail#vX.Y.Z`. npm doesn't build git
     dependencies without a `prepare` script, so the tag carries `dist` (`npm run release`, below).
     _Tested_ with `v0.0.1`.
   - during development, `npm install --install-links ../ed-mail` (after `npm run build` here).
     `--install-links` copies the package instead of symlinking it; a symlink would make the app load
     this repo's own `node_modules/convex` and `react`, two copies of each.
6. **Tailwind 4.** The React package's classes are generated only when the app's CSS has
   `@source "../node_modules/@earthdance/mail/dist";` (Tailwind skips `node_modules` otherwise).
   _Tested_ both ways with `@tailwindcss/cli`. The classes use the shadcn theme token names
   (`bg-muted`, `text-destructive`, ...), so they only get colours where the app defines those tokens.
7. **Function handles.** `createFunctionHandle(internal.x.y)` in an app mutation returns a string
   that can be stored and later called with `ctx.runMutation(handle, args)` from the app's action.
   _Tested_ in `src/client/index.test.ts`. A handle passed into the component is validated with
   `v.function()` / `v.string()` only for shape, not that the function exists.

## Layout

```
src/core       pure TypeScript, no Convex or React; runs in Convex and the browser   @earthdance/mail/core
src/component  the Convex component: tables, queries, mutations; no network, no secrets
src/client     what the app's convex/ code imports (the Mail class)                  @earthdance/mail
src/react      React components                                                     @earthdance/mail/react
src/test.ts    convex-test registration                                             @earthdance/mail/test
example/convex a minimal app mounting the component, for `convex dev` here
```

## Using it in an app

```ts
// convex/convex.config.ts
import { defineApp } from 'convex/server'
import mail from '@earthdance/mail/convex.config.js'
const app = defineApp()
app.use(mail)
export default app

// convex/mail.ts
import { Mail } from '@earthdance/mail'
import { components } from './_generated/api'
export const mail = new Mail(components.mail)
```

```css
/* the app's main CSS */
@source '../node_modules/@earthdance/mail/dist';
```

```ts
// in a convex-test suite
import mailTest from '@earthdance/mail/test'
const t = convexTest(schema, modules)
mailTest.register(t)
```

## Developing

```sh
npm install
npm run build:codegen   # after changing component functions: regenerates src/component/_generated, then builds
npm run check           # typecheck, lint, format check, tests (build first: the example app typechecks through dist)
```

`build:codegen` and `convex dev` need a deployment. This repo uses an anonymous local one (no
Convex account, no quota): the first time, `CONVEX_AGENT_MODE=anonymous npx convex dev --once`
creates it and writes `.env.local`. It runs on ports 3400/3401 so it doesn't collide with
ed-schedule's local backends (3210 and up); if you recreate it, move it back there in
`.convex/local/default/config.json` and `.env.local`.

## Releasing

```sh
npm run release -- 0.1.0
```

From a clean `main`: builds, runs every check, commits the version bump on `main`, puts the tag
`v0.1.0` on a commit just past it that adds `dist`, and pushes both. `main` never holds `dist`.
